Critique · Home (Ford theme)

Artifact: the Home screen as shown in the user screenshot, 2026-10-31 · 5 dimensions · reviewer: Hermes (critique skill)
Mean 5.6/10. The Ford direction holds, but the screenshot shows two Ford marks and two clipped readouts (coolant, battery). Those need fixing before anything else on this screen.

Philosophy consistency

7/10 · Strong

One direction holds across the screen: rounded glass tiles, Barlow type, ice-cyan for live values, white for the speed, amber kept for alarms. Drift: Bluetooth is named three times (BT status pill, 'Bluetooth audio' label, the media card's source), and the screen carries two brand marks, which contradicts the one-mark rule the spec should have stated. The spec in DESIGN.md section 3c listed the oval in the status bar and on Home, so the screenshot follows the spec, not the code.

Visual hierarchy

6/10 · Functional

Speed (74 km/h) is the largest reading, which is right. The Ford mark and the EcoSport title are the loudest brand elements, sitting top-left, and compete with the speed for first read. The Bluetooth card takes the top of the left column (about 310 px tall in the current build), pushing the tiles below into secondary position. Engine on in the header repeats the Engine gauge.

Detail execution

4/10 · Broken

Visible misses in the screenshot: two Ford marks on one screen; the Coolant and Battery readouts are cut off at the bottom edge, so two safety-relevant values cannot be read; the Recent row is cropped; the last nav item is half visible; the Coolant and Battery tiles are shorter than the Fuel card above them, so the right column rhythm is uneven. The current build does not clip (no element extends past 800 px; every text run is 18 px or larger), but it has no Battery tile and no Recent row, so the screenshot is not from the current code.

Functionality

5/10 · Functional

Speed, rpm, boost, fuel and the media title are legible at a glance. Clipped coolant and battery means the driver cannot read engine temperature or battery voltage on this screen, which matters more than any style point. The nav rail shows seven of eight items with the last cut off, and nothing signals that it scrolls.

Innovation

6/10 · Functional

The Ford boot sequence, the masked conic tach and the frame-smoothed gauges are distinctive. The Home screen itself is a conventional card grid (media card, three service tiles, a telemetry column) with no moment specific to this car.

Keep

  • Rounded glass cards with one radius and one gutter (current build).
  • Speed as the dominant white numeral; ice-cyan only for live values; amber only for alarms.
  • One accent family (Ford blue, ice-cyan) with no third hue on Home.
  • 18 px text floor holds in the current build (0 text runs below it).

Fix

  • Keep one Ford mark per screen: the Home header lockup. Drop the status-bar mark (done in the source, see the one-mark check).
  • Make the right column fit: Coolant and Battery inside 800 px with a 16 px bottom margin. Drop Engine load or shorten the Fuel card.
  • Remove the cropped Recent row above the dock, or scroll it on purpose with a visible edge fade.
  • Give the nav rail a scroll cue or cut it to seven items.
  • Use one Bluetooth label (the media card's source) and drop the BT pill duplicate.

Quick wins

  • Delete the orphaned .sb-logo rule (done).
  • Align the header lockup's left edge with the card gutter so both start on one x.
  • Put the gear badge and the Speed label on one baseline.
  • Run tools/design-check.py: it now fails if any screen draws two logos.

Evidence source: the user's screenshot (vision read) plus the current build in headless Chrome. The current build has one Ford mark, no Battery tile, no Recent row and no clipping, so the screenshot is from a different build than the code on disk. Scores describe the screenshot.
